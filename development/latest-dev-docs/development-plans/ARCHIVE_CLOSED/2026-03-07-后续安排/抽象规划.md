> 日期：2026-03-07

## 1. 本文档定位

本文档不是单个功能方案，也不是执行级原子任务表。

本文档只做四件事：

1. 把后续建设方向整理成统一的产品与平台总纲。
2. 给 8 个主题计划提供一致的需求边界和优先级判断。
3. 明确哪些问题是本轮必须回答的，哪些问题暂时不能写死。
4. 为子 agent 重写高质量主题计划文档提供统一输入。

后续所有主题计划都应把本文档视为第一需求来源，而不是只引用最初那段草稿描述。

## 2. 平台当前阶段判断

从当前仓库和已有文档看，平台已经不是“只有采集和展示”的阶段，而是进入以下三条主线并行演进的阶段：

- 从信息采集平台，演进为可组织、可加工、可消费的知识工作平台。
- 从单点 LLM 调用，演进为可路由、可编排、可嵌入业务流的模型能力平台。
- 从统一前端页面，演进为按交互强度分层的工作台体系。

这意味着后续规划不能继续按零散功能点写，而必须围绕三类核心能力来组织：

- 内容工作流能力
- 知识组织与图谱能力
- 平台底层与交互拓扑能力

## 4. 后续建设的总目标

后续规划统一服务于以下总目标：

1. 让平台支持“采集 -> 消化 -> 组织 -> 推理/生成 -> 写作/报告 -> 回流沉淀”的闭环。
2. 让图谱、知识组织、写作工作台不再是孤立页面，而是能共享上下文和中间产物。
3. 让模型能力从业务内嵌工具升级为平台底层能力层。
4. 让前端从功能堆叠页面升级为面向研究工作流的工作台体系。

## 5. 主题拆分原则

后续 8 个主题不是随便分出来的，而是按职责边界拆分：

- 写作与工作台体验，归前端主工作流主题。
- 类型节点、分册、专题聚类，归知识组织主题。
- 图谱编辑、关系同步、图谱到报告，归图谱主题。
- 长文本/PDF/二次产物/长周期任务，归 ingest 消化主题。
- 来源扩张与 crawler 生态，归来源扩展主题。
- 语言/主题/模块化，归前端基础设施主题。
- 多模型/agent/openclaw 类集成，归模型平台主题。
- modern 唯一前端下的双交互工作台拓扑，归前端结构主题。

如果一个需求同时碰到多个主题，规则是：

- 只保留一个主归属主题。
- 其他主题只写依赖和接口，不重复主方案。

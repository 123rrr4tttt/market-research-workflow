# 直接测试与批次封存执行补充（2026-09-12）

依据用户“为啥要不停生成 successor，不能直接测试吗”及“通知执行工作流，并写入开发文档”的指令，即日起适用于当前 MRW 阶段执行与监督。此补充纠正逐小修冻结、交接、等待审批的执行节奏；不修改历史冻结候选，不降低已有阶段退出条件，也不授予发布权限。

## 默认执行方式

1. 在当前工作树或可写测试副本直接修复，并运行已有最小相关测试；不得把生成 successor 作为普通调试、构建或测试的前置条件。记录实际测试输入与结果，避免测试期间输入漂移。
2. 普通缺口由发现问题的执行任务在现有职责内直接处理，不逐项退回 Stage 1/2、不为每个小修新增合同或等待单独审核。只协调真实跨模块变更、共享写冲突、权限或语义选择。
3. 检查范围随受影响行为和依赖确定。相关检查通过且没有新证据即停止扩测和重测；完整 suite 仅在已有阶段或集成交付要求确有需要时执行。
4. 一批修复稳定后，仅在正式阶段交接、替换冻结候选或既有验收确实要求精确身份时统一封存一次。纯机械身份交接解除必要写暂停后可直接发给 Stage 3，不额外等待 Supervisor 单独批准。
5. 已冻结候选、manifest、历史证据保持原样；需要可写运行环境时使用工作树或可写副本。工作树测试结果不冒充冻结候选 exact-commit 结果。
6. 旧证据按实际输入、依赖及环境适用条件核对后复用，明确原执行归属；局部变化不默认使无关证据作废。确实绑定新 commit 的必需检查在真实交付边界补做，不以身份复用冒充新执行。

## 2026-09-13 流程缩减强制规则

适用于本项目开发、测试、CI、证据维护、监督及自动化工作；是项目 `AGENTS.md` 的强制必读内容。本节维护既有补充，不新建合同链。与历史执行节奏冲突时以本节为准，正式阶段退出条件和权限要求不变。

1. **局部修复不升级为发布验证。** 普通开发只运行受影响的已有测试及适用 lint/typecheck。完整 suite、三个角色双重无缓存构建和精确发布验证仅用于已有要求明确需要的集成或交付边界，不因修改一行、文档更新或状态回传重复执行。维护 CI 时应区分普通验证与发布验证；不得直接跳过 required checks、删断言或降阈值冒充通过。
2. **冻结不阻塞日常测试。** 在可写工作树或测试副本完成修复和验证，再在稳定交付批次执行 intake、materialize、record、rebind。身份敏感窗口只协调实际输入及必要写冲突；其他工作区脏改动不是重做无关验证的理由。现有指纹门禁不能绕过；需要修改实现时按实际影响单独验证。
3. **历史身份与当前行为分开。** 冻结快照的 SHA、分母及版本保留原校验；当前行为测试优先验证既有接口和语义，不把新的候选编号抄进无关测试形成连锁修补。真实语义或依赖改变时更新受影响见证，不把失效证据当作有效复用。
4. **先确认扫描通路，保留同批制品。** 完整昂贵构建前先用已有可用制品核对扫描输入兼容性。待验制品在扫描、身份核对及当前交付依赖解除前不得清理；扫描入口失败先修入口，不默认重建镜像。原制品确实丢失才做必要重建，并固定或明确记录可变构建输入；新 digest 不冒充旧 digest 的证据。磁盘不足仅阻塞相关分支，及时说明资源限制。
5. **同一原因只诊断一次。** DNS、依赖缺失、服务未启动等确定性环境问题，记录具体原因、受影响范围和恢复条件；同输入且条件未变时不在多个 selector 中反复复现。恢复条件变化后先跑最小探针，再执行受影响测试。产品缺陷、环境阻塞和未执行项分别记录；不靠跳过检查制造 PASS。
6. **自动维护复用已有结果。** 相同输入、依赖、环境及有效期下优先消费已有结果，避免周健康、业务链回归和专项维护重复同组检查或争抢同一修改。时间敏感的安全扫描、运行健康和性能观察按实际有效期刷新，不因源码未变永久免检。无新证据不新增修复、报告版本或审核；已有自动化配置需要改动时使用正式接口，本文不代表配置已经修改或任务已经暂停。
7. **进度不停等，普通缺口就地处理。** 不逐项退回 Stage 1/2，不以普通回传作为审批点；在已有授权范围内持续完成整个阶段。只对真实权限、语义选择和共享写冲突协调。不得因为某个局部 blocker 停止所有无依赖工作，也不反复唤醒只为确认未变状态。
8. **文档只维护真实入口和状态。** 复用现有开发文档、进度和结果记录，重复身份/metadata 用引用，不手抄多份 hash 表。不因一次措辞纠偏再建合同、schema、validator 或版本链。索引更新依据实际专题状态，不据过期计数宣布全部关闭；无新增事实不重复产生归档计划。文档外脏改动按具体冲突判断，不能一概阻塞不冲突的文档维护；冻结文件、实际归档依赖及用户改动必须保留。

以上是强制执行要求，不是实现完成声明。当前 CI 触发范围、静态构建契约、工作区指纹、候选硬编码测试和自动化配置若仍与目标不符，须记为未落实的具体项；不得为证明“流程缩减完成”在本次文档维护中重跑整套构建或测试。

## 冗余审查后的执行落实（2026-09-13）

以下细化上述规则，不新增阶段退出条件；Stage 4–6 沿用，后续合同引用本节，不复制规则全文。

- **重试从受影响步骤继续。** runner 后段失败，不默认重跑已通过的 migration、schema、快照/恢复和整栈启动。先确认该步骤实际输入、制品、配置及所需数据库/服务状态仍有效，再引用原结果；上游变化只使依赖它的步骤失效。数据库被重置、快照不再可用或证据条件不符时重做相关步骤，不能凭旧 PASS 跳过。优先使用已有分步命令；确实只能从头跑且造成重复时，原执行任务对当前 runner 做最小分步修复，不建通用 checkpoint/调度框架，不为此停止有效在途运行。
- **一次尝试对应实际证据。** 重试前保留必要失败日志，使用既有 attempt 目录或简单不同文件名，避免覆盖后让旧 summary 引用新日志。开发中摘要可更新，但标明运行中/尝试归属；阶段主结果只引用明确归属且已完成的日志，保留被复用结果的原执行身份。共享前置条件失败只记录一个原因及受影响项，未执行的业务项不得写成多次实际失败。构建前确认所需 platform、现存制品和工具入口，避免明显不匹配后才昂贵重试。
- **CI 与冻结问题按真实影响处理。** 普通 PR/push/定时验证与正式发布构建应分开；相同输入、环境、selector 的结果可兼任覆盖率和业务检查，不为同一要求重复执行。落地时保留 required checks 的实际覆盖，不直接改绿或删除门禁。冻结选择边界若为 manifest 输入，指纹实现应匹配实际选择及必要闭包依赖，不以无关 untracked 文件触发全体重做；实现修正前不得绕过现有门禁。CI 和指纹改造不自动成为本地 Stage 4–6 的新交付项，仅在真实阻碍当前路径时最小修复，否则保留为具名后续工程项。
- **当前入口与历史分区。** 06 顶部维护当前阶段、合同和结果入口，18 中旧身份/状态作为历史保留；不继续叠加多个“当前”覆盖段。监督只对整阶段回传作集中验收，普通修复不逐项发放；实现缺口记在原阶段主结果/进度中，不另建审计表、合同版本链或重复 hash 表。

本节为已采纳的执行规则，不宣称 runner、CI 或冻结指纹实现已经修复；是否落实以实际改动及最小相关验证为准。保留阶段实现面、退出条件、安全阈值及下面的验收后清理要求。

## 权限边界（保持不变）

### 阶段验收后清理旧产物（2026-09-13 用户要求）

每个阶段结果经监督审核通过后，由该阶段执行任务完成一次旧产物清理，并将实际清理结果并入现有进度/资源记录。清理是阶段收尾动作，不只登记待办，也不要求用户再次批准已明确无用的任务产物；下一阶段使用的输入先交接确认，清理无依赖旧对象不阻塞下一阶段无冲突工作。

- 删除前只读核对精确路径、Docker 对象 ID/标签、归属、占用及引用。可清理已被替代且不再用于当前验收、下一阶段或约定回滚的任务旧镜像/标签、停止的临时容器、任务专属 builder/cache、重复 OCI/layout 和临时测试副本。不能仅凭名字旧、dangling 或 unused 判断无用；删除标签不保证共享镜像层空间释放。
- 保留当前交付制品及至少一套已核验、确能恢复的必要输入；保留 Stage 5 等后续实际需要的快照/数据/回滚版本。数据库卷、上传文件、唯一源码、冻结候选及不可替代数据不得因“代码可重建”而删除；无法确定依赖的对象单独列明，不阻塞其他已确认对象清理。
- 大体积原始制品确已解除所有验收/复核/恢复依赖时可以删除其旧副本，但保留必要差异证据、日志、结果、原 hash/索引，并在现有生命周期记录注明已删除及恢复方式；不改写历史索引、不将仅存 hash 冒充原始字节仍可复核。当前待验制品在依赖解除前仍禁止清理。
- 仅按核验后的明确对象清理，不执行 `docker system prune`、全局 image/builder/volume prune、宽泛递归删除或 Docker 数据目录重置；不触碰其他任务服务、宿主 Redis、`ops-scrapyd` 及 `Data.backup-20260909-1506`。旧制品保留规则在满足本节条件后解除，不再无期限保留所有重复副本。
- 清理前后记录 Docker/宿主磁盘占用，简要回传已删除对象、实际可确认释放空间、保留理由及可恢复性；区分 Docker 内部可用空间与宿主 `Docker.raw` 实际占用，不把估计字节或移入废纸篓算作已释放磁盘。不为本次规则更新立即停止测试、重跑构建或另建清理平台。

Stage 3 执行任务继续已有授权范围内的实际修复与测试；Supervisor 按阶段性结果集中收敛。本补充不要求重启正在进行的有效测试、不删除历史 successor、不触碰其他任务的运行资源，也不因本次文档修改触发新 successor 或全量重测。

本地测试、构建一致性和身份记录仍不等于远端 CI、registry、签名或生产发布授权。权限上限保持 `LOCAL_DEVELOPMENT_ONLY / NOT_AUTHORITY / PRODUCTION_RELEASE_NOT_AUTHORIZED`。

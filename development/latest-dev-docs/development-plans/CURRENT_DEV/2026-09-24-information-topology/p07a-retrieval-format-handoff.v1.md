## 1. 可调用的结构接口

外部框架新增 `信息结构/` 包，导入时不读取固定调查根。调用方将框架根加入 Python 模块搜索路径后使用以下接口；MRW 的依赖接法由 P00 统一处理，P07B 不应另造导入机制。

| 接口 | 输入与结果 | 边界 |
|---|---|---|
| `load_domain(root)` / `resolve_domain(domain=None, root=None)` | 返回七字段域词表的隔离副本 | 未给参数时沿旧 CLI 同目录行为；P04/P07B 应显式传根或词表 |
| `validate_graph(data, domain=None, root=None, label="图.json")` | 正式口径 2 图的错误列表 | 结构与来源资格检查；通过不证明判断真实 |
| `merge_graphs(graphs)` | 同轮已校验图的合并结果和冲突列表 | 同 ID 判断内容或范围不一致记冲突；调用方先校验 |
| `read_projection(root, paths=None, **selection)` | 轮次目录的只读派生投影 | 投影容纳候选、旧图与警告，不能充当原始事实源 |
| `merge_rounds(root, paths, fast=True, domain=None)` | 跨轮合并后的索引输入字典 | 不写 SQLite；内容冲突和证据隔离仍保留 |

原脚本也接受参数：`校验图.check(data, path, domain=None, root=None)`、`建索引.collect(paths, reader, fast, domain=None, root=None)`、`建索引.build_db(db_path, data, fast, domain=None, root=None)`、`读图.build(paths, ..., root=None)`；`校验图.py`与`建索引.py` CLI 增加 `--root`。旧 CLI 不传根时保留同目录取域、同目录索引与缺口文件的行为。`读图.py`已经有 `--root`；其 `build` 现在可显式接收根。同一进程逐次调用的两个域每次重新取当前词表；P07B 不应跨域共享可编辑的投影对象。

## 2. 原始文件、身份和 owner

| `来源池.md` | 源线 `route:`、池、总纲锚点、章节、视角、拟挂类型/边、入口与状态的 Markdown 表 | 来源路线结构；不等于已核源或执行事实 |
| `初始关键词池.md` | `kw:` 词组表、`query:` 检索式计划表 | 计划结构；`未执行`不等于`未命中` |
| `已固化源.md` | `src:` 源 ID、源线、URL、源状态与快照的 Markdown 登记 | 候选源/已核源身份与核查状态；URL 不直接证明已核 |
| `检索记录.tsv` | 表头为`尝试ID 检索式ID 轮次 线索键 执行时间 工具 实际检索式 结果 源ID 材料ID 下一步 结果说明 原始返回位置` | 真实尝试记录，`attempt:` 逐次新 ID；空表头没有尝试。`命中/未命中/访问失败/偏题`分开 |

## 3. `图.json`口径 2 到检索 profile 的字段映射

`图.schema.json`声明顶层必填：`证据口径`、`线索ID`、`轮次`、`现场`、`生成日`、`节点`、`边`、`证据`、`线索`；`依赖`可选。域值枚举与跨引用由 `校验图.py`补验。P04 应以此作为正式记录形状，再由 profile 精确表达不同关系；不能从只读投影新增的候选字段倒推正式 schema。

| 原记录 | 原始字段 | P04 中应保留的语义 |
|---|---|---|
| 节点 | 必填`节点ID 类型 名称`；可选`现场归属 注册 备注` | 稳定节点身份、域词表类型、显示名称与来源；`现场`是保留节点类型 |
| 边/判断 | 必填`边ID 边类型 从 到 大纲节 关系类 证据ID 判断 范围 判断版本`；可选`中介状态 池 注册 修订自` | 边 ID 是判断身份；`判断+范围+判断版本+从/到+边类型`为内容身份观察项。新证据可保留 ID，实质变更须新 ID 并以`修订自`关联。`修订自`是语义 successor，不是 DB revision |
| 证据 | 必填`证据ID 边ID 材料ID 档 打架 作用 原文定位 原文摘录 适用范围 推论说明 证明对象 来源角色 独立组`；可选`上游材料ID 冲突证据ID` | 证据关系指向判断边与材料；`支持/反驳/限定`不可合并；保留原文定位、来源角色、独立组及冲突引用。档位与事实真实性不能画等号 |
| 线索 | 必填`线索ID 轮次 现场 顺序`；可选`外链 池 链状态 链类 停因 下一跳 门禁跳过 跳过理由 作废 收束说明` | `顺序`是有序数组，包含节点/材料/边/断口引用，重复与位置保持；相邻步骤不自动成为逻辑依赖。`链类`可为检索或实践 |
| 依赖 | 必填`依赖ID 先 后 断否` | 独立逻辑依赖记录；端点为边 ID 或`节:`锚点；不从线索相邻推导 |

证据规则要求正式证据 ID 前缀`ev:`、边`e:`、材料`item:`；证据档只有域声明与 A/B/C/D 的交集可入证据网。D 档仅在`证明对象=表达事实`且`来源角色=直接记录`时允许；A/B/C 仍需字段和引用有效。`打架=是`必须有冲突证据 ID。正式边的原文定位不能由材料档位补造。旧图无整数`证据口径: 2`时，`读图.py`保留节点/边/线索/材料并给待复核警告，不投影旧证据为正式证据。

## 4. P04/P07B 交接判据

1. P04 的 profile 对同一域实例精确绑定七字段；两个不同域连续加载时，类型、池、档、章节判定互不污染。允许原关系指向关系、证据指向判断、线索有序且可重复、明确逻辑依赖有环；不要施加全局 DAG 约束。
2. P07B 导入以原 `图.json`、材料 TSV、原文报告、总纲和准备记录的各自 owner 为准。保留原 ID、轮次、文件路径、原文、判断范围与版本、证据作用/定位、顺序；外部 schema 不认识的 MRW 映射数据另存附加文件。
3. `validate_graph`用于正式图入站校验；`read_projection`用于浏览和候选发现，其`警告`、`冲突记录`及`authority=discovery`必须随导入状态保留。索引合并时冲突边/证据被隔离，不得把“先到值”认作无冲突事实。
4. 往返承诺应按观察项列出：ID、域词表来源、判断内容与范围、证据字段、线索顺序、材料定位。无法在原格式保存的 MRW 字段报告为损失或扩展附加文件，不宣称无损。

5. 检索 profile 的身份由域词表来源绑定，避免所有域共用一个 `(profile_id, version)` registry key。`profile_id` 为 `retrieval.domain.` 加稳定来源引用 `{project_key,module_id,namespace,type_id,local_id}` 的规范 JSON（UTF-8、键排序、紧凑分隔、`ensure_ascii=False`）SHA-256；`version` 为 `1+` 加来源观察版本、`content_digest` 与七字段词表的同规则规范 JSON SHA-256。同一来源的版本/摘要/词表变化保留 `profile_id` 并生成新 `version`；异项目或异来源域即使同名也有不同 `profile_id`。历史状态必须按精确二元组恢复原 profile；缺少该旧版本声明时返回 `UNKNOWN_PROFILE`，不得用当前词表替代。P04 定向测试覆盖两个项目与旧版拒绝。

6. `/imports` 请求的 `source` 须显式包含 `domain_vocabulary` 七字段对象（原键`域名`、`节点类型`、`边类型`、`问题意识视角`、`大纲节`、`池`、`档`）和 `domain_source_ref`：`{ref:{project_key,module_id,namespace,type_id,local_id}, observed_revision, content_digest}`。来源引用必须属于当前项目。适配器调用已参数化 `信息结构.resolve_domain(domain=...)` 对显式词表校验，不读取固定调查目录；缺失或错配不创建 DB 行。拓扑中的 `domain_vocabulary` 元素保存这份观察快照，重启后从持久 payload 重建精确 profile；当前源文件刷新是另一项显式操作，不改变旧快照的解释。

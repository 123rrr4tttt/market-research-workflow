## Execution Notes

- Pool migration is implemented by disabling the active `search_template` entries for the current platform domains in `demo_proj` and retaining their project-level `domain_root` entries.
- Parser enhancement is implemented by writing `extra.remediation` onto the affected `site_entries`.
- Runtime policy resolution now prefers `entry.extra.remediation` before falling back to the static domain policy table.
- No additional global skip rules are introduced in this step.

## Parser Enhancement Focus

General parser enhancement remains centralized rather than site-specific:

1. Prefer structured result-container extraction over global anchor scraping.
2. Filter low-value navigation URLs before term matching.
3. Enrich candidate text from local container context.
4. Prefer article-style detail extraction over raw page text.

This keeps the remediation effort focused on parser capability instead of expanding static routing rules.

## AT-01 Commercial Observer

First execution target under the parser-weak bucket: `commercialobserver.com`.

- Problem:
  - Search resolves, but the current parser over-accepts taxonomy/navigation links before the article headline link.
  - The actual result card lives under `div.card-text` / `div.large-card.card`, while generic `.search-results li` mostly captures navigation.
- Minimal fix:
  - Add `commercialobserver.com`-specific container priority to the shared parser.
  - Prefer `h2 a` / `h3 a` within those cards before generic anchors.
  - Reject non-article URLs for this site unless the path matches article-style date segments such as `/2026/02/...`.
- Acceptance:
  - `commercialobserver.com` should stop preferring category links like `/industrial/`.
  - Result extraction should prefer article URLs under dated content paths.

## AT-02 PYMNTS

Second execution target under the parser-weak bucket: `www.pymnts.com`.

- Problem:
  - Search resolves, but early-page topic and intelligence navigation dominate generic extraction.
  - The parser currently accepts links such as `/topic/ai/`, `/tracker`, `/trendscapes`, and `/pymnts-intelligence` before article URLs.
- Minimal fix:
  - Add a dedicated `site_adaptive.pymnts_card` parser profile.
  - Reject PYMNTS topic/intelligence/navigation paths as low-value candidate URLs.
  - Keep only article-like URLs such as dated news paths or `news/artificial-intelligence/...`.
- Acceptance:
  - `www.pymnts.com` should stop preferring topic pages such as `/topic/ai/`.
  - Candidate extraction should retain article-style PYMNTS URLs when present on the search page.

## AT-03 HAI Stanford

Third execution target under the parser-weak bucket: `hai.stanford.edu`.

- Problem:
  - The search endpoint resolves to a Next.js search shell where global anchors dominate.
  - Generic extraction currently prefers fellowship, education, legal, and accessibility navigation over research output.
- Minimal fix:
  - Add a dedicated `site_adaptive.hai_research_shell` parser profile.
  - Restrict this profile to high-value research/publication paths such as `/ai-index/`, `/research/publications`, and `/policy/publications`.
  - Reject legal, accessibility, education, and off-domain Stanford utility pages.
- Acceptance:
  - `hai.stanford.edu` should stop preferring fellowship and accessibility links.
  - Candidate extraction should retain publication- and AI-index-style URLs when present on the search page.

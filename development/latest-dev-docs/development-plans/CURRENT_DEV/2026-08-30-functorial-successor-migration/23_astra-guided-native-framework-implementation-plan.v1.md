## 目标与必须保持的不变量

1. 能力作者声明领域语义、不可推导内核及必要见证。
2. 固定规则确定的注册、接线、投影和验证接入由工具派生。
3. 同一 authority 边界中的事实只有一个权威声明位置和 writer。
4. 描述、装配、预检与投影不自行获得业务 effect 或事实写权限。
5. 保持对象身份、允许变换及有序复合；不从可组合性推断可交换性。
6. 保持原消费者可观察的结果、拒绝、失败归属与必要恢复边界。
7. 替换按扩展、精化或有损分类；不兼容数据使用明确版本身份。
8. 共享规则由一个 owner 维护；贡献作者不各自复制解析和适配层。
9. 不为本次迁移另建 runtime、scheduler、缓存、审批或证据平台。
10. 保留用户、其他任务与已冻结历史的改动和证据。

## C8 收口

- 主线首先把已有 C8 改动、原消费者入口与未闭合项收敛到同一工作包。
- C8 目标是完成声明到原消费者的实际路径，而不是仅生成注册清单。
- 对已有实现只补当前缺口，不重新派发已完成的同一工作。
- 原生装配与派生投影读取同一语义定义；生成物不得独立手改。
- 每项被依赖的兼容性结论绑定已有类型、证明、测试 ID 或明确偏差。
- 运行受影响的已有检查；输入、依赖和环境未变的结果按原身份复用。
- 完成条件：C8 当前范围的定义、消费者、注册和见证一致，剩余 gap 逐项具名。
- C8 收口不自动建立后续能力完成，也不作为无依赖领域内核的全局阻塞。

## C3 首批

- C3 先选一个当前需求中的真实案例，复用 C8 已证实可用的共同规则。
- 案例与原消费者由主线既有清单确定；本规划不猜测领域词表。
- 若现有规则支持该形状，直接实现其语义贡献及必要特殊内核。
- 若规则无法表达真实需求，只将具体缺口交回规则 owner 修正。
- 规则 owner 先贯通这个案例，再展开依赖同一规则的批量使用。
- 独立内核或已支持形状可并行，共享消费者和清单由集成 owner 统一维护。
- 完成条件：至少一个真实 C3 案例经过原消费者验证，失败与权限边界保持。
- 未确认的规则、源文件或运行命令必须在派发前绑定，不交给多个作者重复摸索。

## 横向 ports

- ports 仅服务当前能力真实需要的资源、权限、生命周期或替换边界。
- 先复用已有 ports；不因术语统一而拆分新服务或预建完整接口族。
- 每个 port 明确输入输出、effect owner、允许权限及可观察失败。
- 领域拒绝、已分类运行失败与未分类缺陷保持可区分。
- 同一语义的 wire、存储和视图表示采用显式有向投影，投影无事实写权。
- port 替换的兼容性通过实际消费者见证，接口形状一致不能代替行为证据。

# 摄取来源

MRW 的来源分为官方来源、开放数据/API、站内搜索、新闻与公告、社交平台和用户直接提供的 URL。具体项目可以选择不同来源组合，但所有入口最终进入同一项目材料、错误和读回边界。

## 来源类型

| 类型 | 适用情况 | 主要边界 |
| --- | --- | --- |
| 官方站点或公告页 | 政策、监管、企业公告 | 页面结构变化、发布日期缺失、重定向 |
| 官方 API/开放数据 | 结构化市场、统计或公开数据集 | 配额、版本、字段语义和更新时间 |
| 站内搜索 | 单一站点内持续检索 | 搜索参数、分页、渲染和反爬限制 |
| 新闻与 RSS | 动态和主题跟踪 | 转载、重复、正文抽取和来源归因 |
| 社交平台 | 舆情、讨论和账号内容 | API 限额、删除、编辑和身份 |
| 用户 URL/文件 | 指定材料或补查 | 访问权限、附件身份、正文质量和版本 |

## 来源身份

一个来源至少应确定：

- 发布方或站点身份；
- 可用 URL、API 或文件入口；
- 适用项目与主题；
- 访问方式和认证；
- 抓取、分页、渲染或抽取策略；
- 更新频率与时间字段口径；
- 风险、限制和失败恢复方式。

来源项不是候选地址。只有实际获取、解析、去重并持久化后的内容才成为项目材料。

## 选择顺序

通常优先使用官方 API 或开放数据，其次官方页面，再次受支持第三方 API，最后使用网页抓取。选择不是固定规则：若官方入口缺字段或不可访问，项目可以组合多个来源，但必须保留来源身份并按字段核对冲突。

## 多源与质量

多源采集应保留：

- 每个来源的原始 URL、获取时间和响应版本；
- 解析器、字段映射和失败原因；
- 候选、已获取正文、已入库材料和索引状态的区分；
- 去重键和冲突处理；
- 数据新鲜度和缺失字段。

同一内容来自多个来源时，不自动合并发布方身份。转载、镜像和聚合页应保留原链接与转载关系。

## 增加来源

新增来源时按现有来源库、resolver、channel 和 adapter 合同接入。先确认现有原生类型能否承载；不要为单个来源增加第二套项目状态、材料 writer 或抓取队列。需要真实权限或不同副作用时，才扩展相应边界。

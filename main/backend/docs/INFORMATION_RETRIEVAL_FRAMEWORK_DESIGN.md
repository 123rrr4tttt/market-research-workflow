# 信息检索、专题调查与知识组织

本文说明 MRW 如何从来源和材料形成可检索观察、专题调查、证据与写作输入。总体对象关系见[架构总览](../../../docs/architecture/README.md)，Agent 接线见[Agent、Cell 与原生 Core](AGENT_MACRO_ARCHITECTURE.md)。

## 1. 分层

MRW 区分四层事实：

1. **来源与通道。** 从哪里发现、能否访问、使用何种抓取或 API。
2. **项目材料。** 某次获取或导入已经过解析、去重和质量边界，并由项目持有。
3. **派生索引。** 为搜索建立的可重建观察，不是原文本身。
4. **研究结果。** 专题运行、证据、知识、分析和报告，各自保有方法与来源。

发现一个 URL 不等于取得材料；取得网络响应不等于完成摄取；写入索引不等于成为项目知识；检索命中也不等于形成证据。

## 2. 来源、通道与候选

来源库记录可复用的来源身份、站点或账号、可用通道和配置。候选地址是待处理线索，只有实际获取、解析、去重和持久化后才进入材料范围。

直接 URL、来源 URL、站内搜索和候选池使用各自既有前门，但共享已经成立的抓取、路由和观察折叠能力。不同入口保留：

- 谁发起获取；
- 使用哪个项目与来源；
- 是否使用搜索词；
- 抓取失败是否允许降级；
- 后处理是否写入候选池、材料或仅返回观察。

来源分类以确定性规则为主。Agent 可以经 Cell 给出建议，但只有明确采纳后才由原领域操作更新分类。

## 3. 材料与项目范围

现行规范实体是 `Material` / `materials`。材料记录原文身份、来源、版本、项目归属、解析状态和可追溯位置；界面资料卡、搜索文档和索引记录都是派生视图。

同一原文可以被不同项目显式收录。项目之间共享原文身份，不自动共享：

- 收录决定；
- 标签和项目知识；
- 可搜范围；
- 专题运行和证据；
- 文档、报告和导出。

普通批量导入逐条提交。一条失败不回滚其他成功项；回执必须能按每条材料读回，失败项保留原因并允许单独处理。

## 4. 索引与搜索

索引服务是派生 writer，不是材料 writer。索引可从材料重建；原文不能从索引反推。

资料库保存新版本后，界面应能显示该版本；索引尚未完成时，旧索引仍可查询。搜索结果必须标出实际命中版本、来源位置和检索模式。索引切换失败不能显示成新版已可查。

普通搜索按当前项目返回材料观察，可以组合：

- 关键词与结构化过滤；
- 向量检索；
- 图谱或关系扩展；
- Web 或站内来源通道。

通道不可用与无命中是不同结果。有存活通道时可以返回不完整结果并标明失败通道；所有必需通道失败时返回类型化失败，不写成功检索记录。

## 5. 专题调查

专题检索是项目级研究运行，不是普通搜索的别名。它持有：

- 项目与研究方法；
- 查询、参数和证据要求；
- 运行标识与版本；
- 输入材料或来源范围；
- 观察、候选、缺口和最终结果；
- 失败、部分完成与续查方向。

普通搜索命中可以被专题运行引用，但不自动成为专题证据。专题方法缺少必需通道时，运行不能标记为完整完成。

Rapid 是项目参数化的检索—再生产循环：结构化采集、材料入库和后续检索可以相互衔接，但生成、受理、保存完成和再次读回仍是不同事实。外部 Agent 或 Cell 只能通过既有项目、工具和授权边界接合，不能直接写数据库。

## 6. 信息拓扑与关系

信息拓扑描述对象身份、类型、关系和观察视图。它不把所有关系都解释为可执行依赖，也不把前端图布局当作领域事实。

| 构造 | 责任 | 边界 |
| --- | --- | --- |
| 类型化知识 | 知识条目、类型关系、主题组织和采纳状态 | 抽取候选不是正式知识 |
| 领域图谱 | 来源和材料中的领域节点、边与证据 | 图页投影可以压缩多元关系 |
| 工作流图 | 运行定义、执行依赖、参数和结果 | 语义关系不自动成为执行边 |
| 线索链 | 调查步骤、证据、取舍和续查 | 不是通用关系存储 |
| 写作大纲 | 章节结构与正文的关系 | 大纲不替代文档版本 |

拓扑装配与 resolver 决定某个原生对象能否被当前消费者解析。不能从存在映射 API 推断历史版本均可恢复，也不能从图页显示推断服务端关系已持久化。

## 7. 知识、证据与写作

内容理解可以产生摘要、实体、指标、关系和主题候选。候选保留来源、抽取方法、版本和置信边界；被抽取不自动成为采纳知识。

知识采纳可以由项目规则自动完成。自动采纳必须保留：

- 原始来源和实际版本；
- 命中规则与采纳依据；
- 知识类型和关系；
- 撤回或替代方式。

证据把判断绑定到原文版本和位置。材料出现新版本时，已有引用不会自动替换；新版可以作为更新提示，但不能静默修改引用卡、报告证据或已交付成果。

写作服务拥有文档、版本和编辑事务。大纲结构归信息拓扑，正文与引用归写作；报告入口负责来源补充、生成、质量观察和导出。允许生成证据不足的草稿，正式交付必须满足模板证据要求。

## 8. 检索失败与恢复

| 情况 | 结果 |
| --- | --- |
| 无匹配 | 成功完成，返回空观察和使用的查询范围 |
| 某通道不可用 | 保留其他通道结果，标记不完整 |
| 所有必需通道失败 | 类型化失败，不写成功记录 |
| 索引版本落后 | 返回旧版可查状态并标明命中版本 |
| 专题方法缺必需证据 | 部分完成或阻断，不标完整 |
| 报告来源为空 | 与取源失败分别记录 |
| 写入结果未知 | 先读回；无法确认且可能有副作用时停止 |

索引可重建，凭据可重新配置。恢复记录不自动恢复在途执行；副作用未知时遵守停止和读回规则。

## 9. 验证要求

检索改动至少验证：

- 项目隔离与归档只读；
- 原文版本、收录和索引版本的区别；
- 批量导入的逐条提交；
- 无命中、部分通道失败、全部失败和 malformed 响应；
- 索引切换前后的可查版本与命中版本；
- 专题运行的完整、部分和阻断；
- 证据、引用和报告版本的固定；
- 真实 Cell 调用与原执行者的持久读回。

单元测试、静态注册或历史搜索结果只证明各自范围，不能替代当前入口的业务链路。

# 日期提取与修复

日期是材料排序、趋势统计和有效时间判断的共同输入。解析器应优先保留原文证据，再选择明确可解释的日期来源，不能用当前时间填补未知日期。

## 支持格式

- ISO 日期和带时区时间；
- 中文年月日；
- 美式与欧式数字日期；
- 英文月份和缩写；
- 财政年度与期间；
- HTML `time`、JSON-LD、`meta` 和正文中的明确发布日期；
- HTTP `Last-Modified` 或文件名日期，作为有标记的兜底来源。

## 提取顺序

1. 结构化字段中的发布日期；
2. JSON-LD 或页面元数据；
3. 正文中的明确发布日期；
4. 经确认的 `Last-Modified`；
5. 文件名或来源声明中的日期，仅在有明确格式时使用。

`created_at` 表示系统收到材料的时间，不等同于发布日期。展示或统计使用 `created_at` 兜底时必须标注口径。

## 歧义与失败

无法区分月日顺序、财政年度或时区时，保留候选和原始文本，不强行选一个日期。未来日期、明显越界日期和抓取时间与发布日期混用应产生诊断。

批量修复必须逐条报告读取、修改和跳过结果；失败的条目保留原值。修复前后均从持久记录读回，不能只根据脚本输出计数。

## 时间字段

材料和文档可以同时保留：

- `publish_date`：来源声明的首次发布日期；
- `effective_time`：规则或政策的生效时间；
- `created_at`：系统接收时间；
- `updated_at`：记录修改时间。

趋势、搜索和引用应使用与问题一致的时间字段，并在结果或界面中标明。

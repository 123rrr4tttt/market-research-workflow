# Local Project Wiring

This capability is registered in the ordinary MRW Agent cell and exposed by the
collector management module. It is an Agent development capability, not a Scrapy
project, crawler deployment, or replacement business runtime.

Read `concept_workbench.module.read` to obtain the targets bound to the current
MRW project. Select the explicitly configured target by identity; do not infer a
host path or operate another project's target.

Load original method content through `concept_workbench.method.read`:

- Begin with `functorial-programming-foundations` for semantic construction.
- Use `workbench-authoring` for project wiring, original native declarations,
  contribution catalogs, and explicit assembly.
- Use `workbench-inspect` for bounded diagnosis and verification.
- Use `library-analysis` when understanding an existing library.
- Read the appropriate companion methods and relative references as the original
  method routes them. Their source files and actual byte digests are returned.

Use `concept_workbench.project.scan` and `materials` with explicit root-relative
paths. A candidate report is not a semantic declaration or completed wiring.
Construct domain meaning, input/output types, effects, ownership and independent
witnesses in the target's original contribution catalog. Reuse the SDK and kit;
do not duplicate their scanner, lowering, composition or registry implementation.

Use `shapes`, `inspect` and `check` to inspect the declared target. Use `init` only
when the selected project needs the original SDK scaffolding; existing files and
conflicts remain governed by that SDK. `sync` writes its derived registrations.
`verify` executes its actual witnesses. Ordinary module work proceeds under the
trusted host policy without per-module confirmation; underlying permission,
sandbox, Core and authority changes retain their original settings owner.

Catalogs, custom scanners and witnesses may execute target code. All these tools
use the original CLI and return its exit code, stdout, stderr and JSON report.
A non-zero exit is a failure. Structural registration, assembly and witness
results have their own scope and do not establish crawler deployment, runtime
adoption or domain completion.

# MRW 管理页面呈现规划

日期：2026-09-26。状态：2026-09-27 已实施首批管理页改版；实施与验证记录见第 9 节。

目标：让用户进入管理页后直接辨认当前对象、作用范围、运行情况和可执行操作。范围为 Layer C 管理面及其与工作台、可视化的导航关系。保留现有事实 owner、执行入口与权限。第 1–8 节记录 2026-09-26 的规划与示意，第 9 节记录后续实施。

## 1. 现状与首要判断

本轮读取当前工作树，并查看 `http://localhost:5174/` 的管理任务页及 `#/admin/projects`。任务页检查了约 667px 窄窗口与 1440px 桌面宽度；项目页读取了实际页面内容。其余管理子页以代码审计为依据，未宣称全部完成浏览器交互验证。

| 已观察到的问题 | 依据 | 呈现后果 |
| --- | --- | --- |
| 每个管理子页在正文之前挂载完整业务链说明，默认展开 | `AdminLayerShell.tsx`；`BusinessChainGuide.tsx:18` | 桌面首屏几乎没有任务正文；切换页面仍先读同一张说明图 |
| 深色壳与浅色说明卡片互相覆盖 | `index.css:573` 的浅色 guide；`:743` 起的管理层通用 `color: inherit` | 浅底上的部分标题、说明继承浅色文字，肉眼难以辨认 |
| 图中文字极小且依赖横向滚动 | `index.css:588` 的 1300px 最小宽度、`:592` 的 8px 细节文字 | 承载架构说明尚且吃力，更不适合管理页默认首屏 |
| 全局诊断和项目操作占据页面最上方 | `AdminLayerShell.tsx:151` 起：六项状态、目标项目、激活、模板注入、流程主页 | 低频操作与当前页面内容争夺注意力；窄屏整段纵向堆叠 |
| `ready` 的含义混杂 | `useKernelRuntime.ts:141`：模型/搜索/新闻/数据库状态由配置键存在性计算 | 用户容易把“有配置”误读为“连接正常”；未知、读取失败与未配置也需区分 |
| 项目列表排在创建表单与 readiness 之后 | `ProjectsPage.tsx:145`、`:188`、`:243`；实际页面读回 | 日常查找项目需要越过低频创建配置；表格先暴露 schema 和布尔值 |
| 管理导航重复声明，设置和 Ops 长页混合不同范围 | `ADMIN_GROUPS` 与 `moduleManifest` 并存；Settings/Ops 代码 | 同一对象在不同视图的分组可能漂移；无法直观看出操作影响项目还是全局 |

优先处理信息顺序、样式作用域与状态含义，然后整理子页。不以换配色、增加统计卡片或重写后端作为第一步。

## 2. 同类平台的参考方式

以下为官方公开材料中的交互模式；不是对这些平台登录态后台进行完整体验后的评分。

| 参考 | 已核对的模式 | 用于 MRW 的设计选择 |
| --- | --- | --- |
| [n8n：View all executions](https://docs.n8n.io/build/understand-workflows/understand-executions/view-all-executions.md) | 执行记录按实例/项目查看，按状态、工作流、时间筛选 | 运行记录以列表和筛选为主体，详情关联结果与失败原因；具体重试能力仍由 MRW 原入口决定 |
| [Dify：知识库创建与设置](https://dify.ai/blog/create-knowledge-in-dify-for-beginners) | 知识库作为独立对象；导入后分组配置分块、索引和检索 | 来源/资料对象与连接配置分层，常用项先出现，高级参数按组展开 |
| [Linear：Display options](https://linear.app/docs/display-options) | 列表可调整展示字段、分组、排序；展示选择与筛选不同 | 高频管理对象用可扫描列表；默认少量核心列，按需增加技术列，保留用户的筛选位置 |

采用克制的业务后台风格：中性背景、清楚的行分隔、稳定的导航、明确的当前行与状态。工作流画布和图谱继续保留各自的专业工作面。

## 3. 页面职责与信息架构

管理面主要服务三个问题：当前项目有什么、哪些执行需要处理、配置影响哪里。先展示对象和结果，再提供操作和诊断。前端汇总不建立新的任务状态、资料质量结论或执行权限。

建议形成两个导航分组、八个最终入口；第一批不新增“概览”，继续以运行记录作为管理默认页。

| 分组 / 入口 | 页面主内容 | 当前模块映射与范围 |
| --- | --- | --- |
| 项目工作 / 管理概览（后置） | 待处理事项、最近运行、已确认的资料结果 | 复用现有 Process/Ops 读模型；只有统计口径和 scope 对齐后增加 |
| 项目工作 / 运行记录 | 当前项目的运行、完成、失败记录 | `overviewTasks` / `ProcessPage`；全局 worker 队列独立标识并放入系统运行，不能伪装成项目任务 |
| 项目工作 / 资料与质量 | 资料列表、质量结果、相关证据 | `overviewData` / `OpsPage` 中相应视图；资料结果与治理动作分层 |
| 项目工作 / 来源与采集 | 来源库、爬虫、提取记录三个子页 | `sysResource`、`sysCrawler`、`flowExtract`；共用导航分组，资源配置与部署/回滚仍归原 owner |
| 项目工作 / 数据处理 | 处理任务、失败原因、关联资料 | `flowProcessing` / `ProcessPage variant=processing`；运行记录中的专用过滤视图，不复制任务事实 |
| 平台管理 / 项目与模板 | 项目列表、项目详情、模板初始化 | `sysProjects`；项目目录为全局，进入具体项目后明确显示目标项目 |
| 平台管理 / 模型与连接 | 模型服务、外部连接、配置作用范围 | `sysLlm`、`sysSettings`；环境连接与当前项目模板分开标识；个人语言/主题进入偏好设置 |
| 平台管理 / 系统运行 | 服务健康、worker/队列、运行诊断 | `sysBackend`、`sysSuccessorRuntime` 子页；全局服务与项目 Runtime 分栏标识，Successor 保持只读 |

名称“资料与质量”比“数据”更具体；不得把已入库、已索引、已通过质量检查压成一个“可用”标签。若某一来源或爬虫接口是全局范围，页内明确展示“全局资源 / 当前项目绑定”，不能仅依据顶部选中了项目就声称已隔离。

用户界面保留“工作台 / 可视化 / 管理”切换，A/B/C、Layer C、management surface、内部 route 不再作为常驻标题。旧 URL 和 legacy hash 继续可达，导航分组改变不要求立即改 URL。

## 4. 通用页面骨架

桌面布局：约 200px 左侧导航；顶部 56–64px 上下文栏；主体按“标题与主操作 → 筛选 → 列表 → 详情”排列。当前项目显示中文名称，标识作为次级信息可复制。只出现一个项目切换入口，切换完成后同步标题、URL 状态、查询范围与错误反馈。

- 顶部只保留产品/工作面、项目上下文、必要的系统通知与偏好入口。系统异常可点击进入诊断；没有新观测时显示“未检测/上次检测时间”，不合成“全部正常”。
- 页标题 22–24px；一行用途说明；每个页面最多一个突出主操作。运行页不为凑按钮增加“新建任务”，创建入口按业务类型回到已有工作台。
- 列表默认 5–7 列，首列为人可读名称，ID 降为次级信息。常规行高 44–56px；筛选位于列表正上方，批量操作只在选中记录后出现。
- 详情按“结果摘要 → 关联对象/影响 → 失败原因或操作 → 技术详情”排列。宽屏可使用 380–460px 侧栏；宽度不足时用行下详情或独立详情页，保留返回后的筛选和位置。
- 业务说明进入侧栏底部“帮助 / 业务说明”，可在新用户首次进入时提供短提示。完整架构图只在用户主动打开时展示，并支持放大；不在各子页重复默认展开。
- 页内帮助优先解释字段的业务含义。API 路径、worker 主机名、JSON、schema、原始错误堆栈放入可复制的技术详情。

项目选择只是界面上下文；已有 `activateProject` 是实际命令。第一批保留其成功/失败契约，不能将纯浏览选择自动变为全局激活。模板注入移入项目详情的初始化操作，展示目标项目和覆盖影响；保留已有确认与权限，不增加无关审批。

## 5. 关键子页的具体呈现

### 运行记录

默认展示“全部 / 进行中 / 失败 / 已完成”，支持类型、日期、名称过滤。主列为任务名称、类型、执行状态、数据结果、开始时间、耗时、详情入口；屏宽有限时合并名称与类型。状态计数说明是否仅当前页或全量，不能把客户端分页计数当全库计数。

任务完成与数据结果分开，例如“已完成；新增 12、重复跳过 2”。未读回结果显示“等待结果读回”，空记录显示“暂无任务”，请求失败显示“读取失败”和重试。失败详情保留原始原因；取消、重试、审批仅在后端支持且当前权限允许时出现。

### 项目与模板

先展示项目列表：名称、当前项目标记、启用/归档状态、说明、更多操作。点击名称打开详情；创建用独立表单/抽屉；模板+提示词创建归入“从模板创建”的步骤。`project_key` 可查可复制，schema、enabled、is_active 等放入技术信息。

readiness 首先用一句准确摘要说明“最低提交配置是否具备”，按需展开检查证据；不提升为“项目已经可完成研究”。归档、删除、覆盖初始化进入对应项目的更多操作区，避免每行同时出现多个同等醒目的破坏性按钮。

### 来源与采集

来源列表以名称/域名、类型、项目绑定、最近采集观测和相关操作为主。无真实最近采集记录时显示“暂无记录”，不把存在配置等同于采集成功。爬虫详情拆成配置、部署版本、运行记录；导入、部署、回滚只在对应上下文中出现。提取记录链接回来源和产出，不另造一份事实。

### 模型与连接

先按服务或用途展示列表，如模型、搜索、新闻、存储。点击编辑出现可读标签、说明、作用范围和保存状态；环境变量名作为辅助标签。复杂 prompt 与高级参数进入专门区域。凭据维持遮蔽与原有写入方式，不把密钥放进汇总或预览。

配置状态使用“已配置 / 未配置 / 读取失败”；连接观测使用“正常 / 异常 / 未检测 / 已过期”；认证状态使用“已登录 / 未登录”。禁止仅靠同一个 ready 布尔值同时生成三种结论。

### 系统运行、资料与质量

系统运行先显示服务名称、最新观测、时间与异常原因，日志和队列展开查看；业务证据矩阵放入资料与质量或对应记录详情。治理的 preview→execute、已有审批和作用范围保持原顺序，不能用“处理异常”快捷按钮跳过步骤。WorkflowManager 仍属于工作台，只提供相关运行/定义的跳转。

## 6. 视觉、交互和状态规则

复用 `app/platform/theme/tokens.ts` 现有 light/dark/brand 色板与 Lucide。管理面也消费同一套 token，清理硬编码黑底、整层 `color: inherit` 和覆盖所有控件的 `!important`。组件自行声明背景与前景配对，不能只替换背景。

正文/表格建议 14px，辅助文字 12–13px，正常行高约 1.5；技术等宽文字至少 12px。取消导航和中文界面中的大段全大写、过宽字距；状态用文字加颜色，不只依赖颜色。视觉验收采用正文至少 4.5:1 的对比目标，且检查实际背景组合。

| 状态 | 呈现 |
| --- | --- |
| 首次加载 | 保留页面骨架与列头，显示加载状态，不先填 0 |
| 后台刷新 | 保留已有内容和更新时间，局部标记刷新，不让布局跳动 |
| 真正为空 | 解释当前范围下无记录，并给出有意义的已有入口 |
| 筛选为空 | 保留筛选条件，支持清除，不显示“系统无数据” |
| 部分失败 | 仅在失败区域显示原因与重试，其他已知数据继续可读 |
| 权限不足 | 显示受限操作及原因；不能通过前端导航变化扩大权限 |
| 已配置但未观测 | 显示“已配置 · 未检测”，不显示绿色健康结论 |

1440/1280 宽度展示完整列表；1024 左侧导航可收窄，详情改行下展开；768 以下导航进入可开合菜单，顶部紧凑，操作分组收起；390 宽度优先展示名称、状态、结果摘要，其他字段进详情。整页不横向滚动，必要的原始日志/数据表只在其局部滚动。200% 缩放、长中文名称和英文 ID 不能裁掉关键状态。

测试资源由集成 owner 统一安排：类型/静态脚本可按只读输入并行；build、Storybook、Playwright 的输出目录与服务端口不可默认并发。默认 E2E 使用隔离的 4173 与 fail-closed proxy；若端口被占用，先确认归属并设置空闲 `FRONTEND_E2E_PORT`，不复用用户服务冒充隔离测试。

所有命令的 cwd 为仓库 `main/frontend-modern`，采用 package.json 已存在入口；按当前改动选择相关项目，不因规划新增全量发布门禁。

```bash
npx playwright test tests/e2e/successor-runtime-page-wiring.spec.ts tests/e2e/successor-runtime-observation.spec.ts --workers=1
```

上述是计划中的验证命令，不是本轮 PASS。已有检查若绑定被替换的呈现结构，应保持语义断言并调整结构断言；不得删掉功能覆盖。缺少的关键交互在既有 E2E/Storybook 中补充有界用例，无需为每个 CSS 值新增测试。

产品验收场景：

1. 1440×900、1024×768 首屏可看到当前页面核心对象/列表第一条；390×844 不先堆出整段导航与诊断。
2. 找到失败任务、打开具体原因和相关结果，最多两次明确点击；未实现的重试不能显示为可用操作。
3. 项目页先看到名称与状态；创建、模板初始化、归档/删除均有明确对象上下文。
4. 切换项目失败不导致旧数据被标成新项目；成功后页名、筛选范围、缓存与请求一致。
5. 设置保存前可判断“全局 / 当前项目 / 个人偏好”；配置成功与服务观测不混淆。
6. URL、侧栏选中、页标题、子页标签一致；旧链接和浏览器前进/后退仍有效。
7. 键盘可操作筛选、详情和菜单；详情关闭回到原入口；缺数据、长文本、浅深色与缩放均可读。

本轮可点击示意仅演示运行列表、状态筛选、搜索、详情展开和密度选择，数据均明确标为示例；它不连接 MRW，也不代表这些新呈现已经接入现有 API。
